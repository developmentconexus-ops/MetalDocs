# (tools/verify/registry.go, check id "oasdiff-breaking").
#
# This is the honest waiver channel for a DELIBERATE, disclosed breaking
# change -- not a bypass. It has the same audit properties as
# scripts/check-governance-waivers.txt: every line here is a permanent,
# diff-reviewable record (this file sits under api/openapi/v1/, so any edit
# to it is itself covered by the oasdiff-breaking check's own Paths and by
# api-contract-openapi). A line here does not silence oasdiff's *detection*
# of the change (it is real, and is documented in the PR's "Behaviour
# preservation" section) -- it only tells the gate that this specific,
# named change was reviewed and is intentional, so CI does not fail on a
# finding a human already adjudicated.
#
# Matching is oasdiff's own (checker.ProcessIgnoredBackwardCompatibilityErrors,
# case-insensitive): a line must contain both "<METHOD> <path>" and the
# change's own text verbatim. Each line below is the exact text `oasdiff
# breaking` prints for one of the four findings, copied from a real run
# against base commit aaafe8bd -- not hand-written, so it cannot silently
# drift from what the tool actually reports.
#
# A3.4 (PR #112), 2026-08-11: four routes gained a required request field
# that was already de facto required. The mechanism differs by route --
# see the two paragraphs below -- do not read them as interchangeable.
#
# The THREE session routes (force-release, heartbeat, release): the handler
# previously read `session_id` optimistically and, when it was absent/empty,
# forwarded it to a downstream Postgres `uuid`-typed column (editor_sessions.id),
# which rejected it at the driver/server level. That produced a 500
# (`internal.unknown`) for a client mistake instead of a 400
# (`request.invalid`) -- mapErr's dispatch table has no case for that
# rejection, so it fell through to `default:`. Declaring the field required
# in the OpenAPI spec moves that rejection into the contract-validation
# middleware, before the handler runs, turning a latent 500 into an honest
# 400. There is no client that could have been relying on success for an
# absent/empty session_id, since the old path never succeeded on one.
#
# The PLACEHOLDER route (PUT .../placeholders/{pid}) is NOT the same
# mechanism -- there is no Postgres uuid column in this write path, and the
# old behaviour was not a uniform 500. Pre-A3.4, `fillin_handler.go` decoded
# an absent "value" to "" with no decode error, and
# FillInService.SetPlaceholderValue -> validateCommonConstraints
# (internal/modules/documents/application/fillin_service.go:215-218)
# rejects an empty value only when the TARGET PLACEHOLDER's own
# author-editable `Required` flag (templatesdomain.Placeholder.Required,
# internal/modules/templates/domain/schemas.go:97) is true. For any
# non-required placeholder -- an ordinary case, not a corner case --
# `PUT {}` with no "value" key used to succeed (200, empty string
# persisted). Declaring `value` required at the contract layer makes that
# same omission 400 unconditionally, regardless of the target placeholder's
# own Required flag. This IS a real behavioural narrowing for that specific
# shape (omit-value-on-a-non-required-placeholder), not just a 500-to-400
# reclassification. It ships anyway because a `grep` across
# frontend/apps/web/src found no feature code calling this route with an
# absent `value` (only generated client types reference it) -- no known
# consumer depends on the old success path -- but this line's "de facto
# already required" framing does NOT hold for this route the way it does
# for the three session routes, and is recorded honestly here rather than
# folded into the uuid-column story above.
#
# A parallel, still-open gap for the placeholder route: contract_validation
# has no `minLength: 1` on `value`, so an explicit `{"value":""}` (as
# opposed to an absent key) still reaches the handler unrejected, the same
# residual shape as DocumentSessionIdRequest.session_id's known
# empty-string gap (see
# apps/api/cmd/metaldocs-api/validator_ingress_session_routes_test.go's
# TestIngress_SessionRoutes_EmptyStringSessionID_StillReachesHandler_KnownGap).
# Scoped out of this round for the same reason: closing it requires a
# separate spec tightening (minLength) plus its own disclosure, which
# belongs with a dedicated fix, not silently bundled into this waiver.
#
# New coverage proving the 400-before-handler path (through the real
# middleware chain, not the bare handler mux) for all four routes lives in
# apps/api/cmd/metaldocs-api/validator_ingress_session_routes_test.go.
#
# This file becomes inert (matches nothing) the moment these four lines
# merge to main, because every future PR's base spec will already have the
# fields marked required -- oasdiff will have no "added required" diff left
# to find here. Left in place rather than deleted post-merge, same as the
# governance waivers file: it is the historical record of why the contract
# changed shape on these four routes.
PUT /documents/{id}/placeholders/{pid} added the new required request property `value`
POST /documents/{id}/session/force-release added required request body
POST /documents/{id}/session/heartbeat added required request body
POST /documents/{id}/session/release added required request body
