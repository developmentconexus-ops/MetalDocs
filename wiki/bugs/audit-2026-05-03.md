## Cross-cutting observations (not fixing now)

- **Document families have no tenant isolation** — global table, any tenant can rename families another tenant uses. Long-term: add governance or make families system-managed.
- **`locked_at` column is dead code** — added in 0131/0167, zero Go references. Drop in future migration.
- **`finalized` status in CHECK constraint is unreachable** — legacy value. Drop in future migration.
- **Two area membership code paths** (`area_membership.go` SQL functions vs `AreaMembershipService` direct writes) — maintenance hazard. Pick one.
- **`RegistryService.Create` has nil-DB branch** with sequence leak on failure — remove nil branch.
- **Fanout client uses `http.DefaultClient` with no timeout** — hung docgen-v2 stalls all signoffs. Add 60s timeout.
- **`composition_config` wrapped twice as `json.RawMessage`** — dead code wrapper, harmless but confusing.

### H3 detail
**Files:** `internal/modules/documents/application/freeze_service.go:112,127` · `internal/modules/documents/application/draft_resolver_service.go:57`

`templates/domain/schemas.go` defines two separate fields: `Type PlaceholderType` (values: `"text"`, `"computed"`, etc.) and `Computed bool`. The template builder stores computed placeholders as `"type":"computed"` in JSON, which deserializes to `p.Type = PHComputed`. But `freeze_service.go` and `draft_resolver_service.go` both gate on `p.Computed` (the bool field), which is never set from the JSON `"type"` key. Result: all computed resolvers are silently skipped. No placeholder values are written (`document_placeholder_values` stays empty). Fanout receives `PlaceholderValues = {}` → all `{placeholder}` references in the template DOCX replaced with empty string.

**Evidence:** PROC-01 template has `Codigo: {doc_code}` in body DOCX. `public.document_placeholder_values` has 0 rows for revision `de73e5ff`. PDF shows `Codigo:` only.

**Fix:** Added `isComputed` helper in `freeze_service.go` that checks `p.Computed || p.Type == PHComputed`. Same fix applied in `draft_resolver_service.go`. Also found in tandem: `draft_resolver_service.go:57` had the identical gate.

**Also related — H2 fix:** `pdf_job_runner.go` now derives `frozen.docx` path deterministically from `tenantID + revisionID` when `final_docx_s3_key` is absent from payload, instead of failing.
