### A7 detail — Route admin stage destroy (FIXED 41ca209d)

**Files:**
- `frontend/apps/web/src/features/approval/pages/RouteAdminPage.tsx:49` — `toDraft` (fixed)
- `frontend/apps/web/src/features/approval/pages/RouteAdminPage.tsx:7` — `StageDraft` (extended)

### B1 detail — DELETE-then-INSERT (FIXED 25ca0290)

**File:** `internal/modules/iam/infrastructure/postgres/role_admin_repository.go`
ON CONFLICT target was `(user_id, role_code)`. Post-0166 unique constraint is `(tenant_id, user_id)`. Any multi-role or role-change assignment hit unique violation → 500.
**Fixed:** Both `UpsertUserAndAssignRole` and `ReplaceUserRoles` now DELETE from `iam_user_roles WHERE tenant_id = $1::uuid AND user_id = $2` before INSERT. No ON CONFLICT clause on role INSERT rows. Unit tests: `TestUpsertUserAndAssignRole_PassesTenantID`, `TestReplaceUserRoles_DeleteThenInsert_OnlyLastSurvives`.

### B2 detail — Two-tier boundary documented (FIXED f951f99e)

**Files:** `internal/modules/iam/application/capability_service.go`, `internal/modules/iam/authz/authz.go`
Route middleware uses `CapabilityService` (reads `iam_user_roles`, Tier 1). In-transaction handlers use `authz.Require` (reads `user_process_areas`, Tier 2). No backfill between them. User assigned via IAM admin UI passes middleware but fails area-scoped authz.
**Fixed:** ADR 0007 (`wiki/decisions/0007-two-tier-authz-boundary.md`) formally defines the two-tier contract. `CapabilityService` doc comment updated to clarify tier responsibility. The two tiers remain separate by design — area membership is the correct gate for in-document operations.

### B3 detail — Dev approver role corrected (FIXED fef30f8b)

**Files:** `migrations/0159_seed_dev_approver_user.sql`, `migrations/0170_fix_dev_approver_role.sql`
Migration 0166 blanket renamed `admin → system_admin` in `iam_user_roles`, catching the dev approver account seeded by 0159. Result: both admin and approver were `system_admin` in dev — SoD never exercised.
**Fixed:** Migration 0170 corrects the dev approver's role to `approver`.

### B4 detail — Typed GUC errors (FIXED aabccfde)

**Files:** `internal/modules/iam/authz/context.go`
`current_setting('metaldocs.actor_id', false)` raised `42704` (undefined parameter) outside modules that set the GUC. Changed to `missing_ok=true` + typed error `ErrActorContextMissing` / `ErrTenantContextMissing` so callers can handle gracefully.

### B5 detail — RolesByUserID tenant isolation (FIXED d675da39)

**Files:** `internal/modules/iam/infrastructure/postgres/role_provider.go`
`RolesByUserID` SQL only filtered by `user_id`. Cross-tenant role bleed: user in tenant A would see roles assigned in tenant B.
**Fixed:** SQL now filters by `user_id = $1 AND tenant_id = $2::uuid`. `CachedRoleProvider` cache key changed from `userID` to `userID + "|" + tenantID`. Integration test: `TestRoleProvider_TenantIsolation`.

### B6 detail — HasAnyRole tenant isolation (FIXED 589631f6)

**Files:** `internal/modules/iam/infrastructure/postgres/role_admin_repository.go`
`HasAnyRole` SQL only filtered by `role_code`, not `tenant_id`. Bootstrap admin skipped if *any* tenant had `system_admin`.
**Fixed:** SQL now includes `AND tenant_id = $2::uuid`. Unit tests: `TestHasAnyRole_FiltersByTenant`, `TestHasAnyRole_OtherTenantReturnsZero`. Integration test: `TestHasAnyRole_TenantIsolation`.

## Cross-cutting observations (not fixing now)

- **Document families have no tenant isolation** — global table, any tenant can rename families another tenant uses. Long-term: add governance or make families system-managed.
- **`locked_at` column is dead code** — added in 0131/0167, zero Go references. Drop in future migration.
- **`finalized` status in CHECK constraint is unreachable** — legacy value. Drop in future migration.
- **Two area membership code paths** (`area_membership.go` SQL functions vs `AreaMembershipService` direct writes) — maintenance hazard. Pick one.
- **`RegistryService.Create` has nil-DB branch** with sequence leak on failure — remove nil branch.
- **Fanout client uses `http.DefaultClient` with no timeout** — hung docgen-v2 stalls all signoffs. Add 60s timeout.
- **`composition_config` wrapped twice as `json.RawMessage`** — dead code wrapper, harmless but confusing.
