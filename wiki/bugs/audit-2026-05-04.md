## Group J — Auth & Approval Security (Critical)

**Spec:** `docs/superpowers/specs/2026-05-05-auth-approval-hardening-design.md`

| # | Bug | Severity | Status | Fix commit |
|---|-----|----------|--------|------------|
| J2 | `permissiveAuthzChecker` in `main.go` returns `nil` for every check — `document.create` authz completely bypassed | 🔴 critical | **fixed** | 563d650e, c0fa0485, 7b26f3cd, 1cebea64 |
| J1 | `RecordSignoff` never checks actor ∈ `eligible_actor_ids` snapshot — any area-capable user can sign | 🔴 critical | **fixed** | 7ec9e4db, b154b9a8, d973bd5b, de7411b0, 10aeefe5, 67d795f9 |

### J2 detail — permissive authz removed (FIXED)

**Files:**
- `apps/api/cmd/metaldocs-api/main.go` — `permissiveAuthzChecker` struct (lines 482-487 in pre-fix) removed; `wiring.NewCapabilityChecker(capabilityService)` wired at :275
- `apps/api/internal/wiring/documents.go` — new wiring file; `NewCapabilityChecker` at :24

`permissiveAuthzChecker` was a struct that implemented `AuthorizationChecker` by returning `nil` for every capability check. It was wired into the documents module at startup, meaning `document.create` (the sole call site at `internal/modules/documents/application/service.go:240`) was never actually enforced.

**Fixed:** `AuthorizationChecker` interface deleted from the documents module. A typed consumer port `CapabilityChecker` (`internal/modules/documents/application/ports.go`) replaces it. Production wiring now binds `*iamapp.CapabilityService` directly via `wiring.NewCapabilityChecker` (adapter in `apps/api/internal/wiring/documents.go:24`). Documents wiring lifted out of `main.go` into the dedicated wiring file.

### J1 detail — signoff eligibility enforced (FIXED)

**Files:**
- `internal/modules/documents/approval/domain/eligibility.go` — pure rule `CheckEligibility`
- `internal/modules/documents/approval/application/decision_service.go:158-170` — service call + audit event on rejection
- `internal/modules/documents/approval/repository/postgres_approval_repository.go:305-316` — `loadStageInstances` SELECT … FOR UPDATE (prevents re-snapshot during signoff)
- `internal/modules/documents/approval/http/errors.go:48-50` — `ErrActorNotEligible` → HTTP 403 `signoff.not_eligible`
- `migrations/0180_signoff_eligibility_trigger.sql` — DB trigger defense in depth

`RecordSignoff` called `authz.Require` and `CheckSoD` but never verified the actor was in `eligible_actor_ids` frozen at submit time. Any user holding the area-scoped `doc.signoff` capability could approve — including users not named on the route stage.

**Fixed (defense in depth):**
1. `domain.CheckEligibility(actorUserID, activeStage.EligibleActorIDs)` — pure function, returns `ErrActorNotEligible` if actor absent.
2. `decision_service.RecordSignoff` (step 5b, :158-170) calls it after `authz.Require`, before `CheckSoD`; emits `signoff.rejected` governance event with `reason=not_eligible` on failure.
3. `loadStageInstances` acquires `FOR UPDATE` lock on stage rows (:305-316) to prevent concurrent re-submit from snapshotting a new `eligible_actor_ids` while a signoff is in flight.
4. Migration 0180 installs a `BEFORE INSERT` trigger on `approval_signoffs` that checks the actor against the stage's `eligible_actor_ids` jsonb — DB-level belt to application braces.
5. HTTP layer maps `ErrActorNotEligible` → 403 `signoff.not_eligible`.

## Group M — Fanout / PDF Pipeline

**Spec:** `docs/superpowers/specs/2026-05-05-auth-approval-hardening-design.md`

| # | Bug | Severity | Status | Fix commit |
|---|-----|----------|--------|------------|
| M1 | `fanout.NewClient` passed `nil` http.Client — no timeout, default connection pool | 🟡 medium | **fixed** | 716f2f1f, 8f7e5fc8, 2798d75c |

### M1 detail — fanout client timeout (FIXED)

**Files:**
- `internal/platform/httpclient/internal_client.go:12-30` — `NewInternalClient` factory, tuned Transport
- `apps/api/cmd/metaldocs-api/main.go` — `fanout.NewClient(fanoutURL, serviceToken, httpclient.NewInternalClient())` replaces `nil`
- `internal/modules/documents/approval/application/decision_service.go` — legacy `pdfDispatcher.Dispatch` wrapped with 45 s context deadline

`fanout.NewClient` accepted a `*http.Client` parameter; passing `nil` fell back to `http.DefaultClient` which has no timeout and `MaxIdleConnsPerHost=2`. If Gotenberg hung, goroutines leaked indefinitely.

**Fixed:**
- `internal/platform/httpclient` package introduced. `NewInternalClient()` returns `*http.Client` with `Timeout: 60s`, `ResponseHeaderTimeout: 10s`, `MaxIdleConnsPerHost: 20`, `MaxConnsPerHost: 50`, `ForceAttemptHTTP2: true`.
- Production wiring passes `httpclient.NewInternalClient()` to `fanout.NewClient`.
- Legacy `pdfDispatcher.Dispatch` (deprecated post-outbox path) wrapped with a 45 s per-call context deadline as belt-and-braces.
