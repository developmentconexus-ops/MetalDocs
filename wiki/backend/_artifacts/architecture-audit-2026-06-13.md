# Independent Architecture Audit — 2026-06-13

> **Method:** 10-dimension multi-agent audit (39 agents, ~2.27M tokens) reading the **actual code** (not wiki claims), grading each subsystem A–F against industry standards. Every Critical/Major finding was sent to an independent skeptic that confirmed, downgraded, or **refuted** it against the code. This is a *fresh* read independent of the Wave 0–Z program: it surfaced ~23 verified defects that were never in the legacy register (mostly structural/architectural).
> **Branch:** qa/iam-area-membership. **Trigger:** operator asked whether the backend architecture (as designed AND implemented) is genuinely industry-grade before moving to screens.
> **Headline:** Solid **B / "good senior Go."** The craft is real; debt is concentrated in three *structure* dimensions (module boundaries, contract integration, composition root). NOT a rewrite — a bounded, fixable list.

### H-PRE-1 — system_admin CD-create self-deadlock (prereq, discovered during H-6b runtime-verify)

✅ RESOLVED — (this commit). **Not an original audit finding**; surfaced when runtime-verifying H-6b (the duplicate path routes through CD-create).

**Root cause.** CD-create's atomic tx (`controlleddocuments/application/service.go` `s.runner.Do`) acquires the audit hash-chain advisory lock `pg_advisory_xact_lock(90120260513004)` the moment `authz.Require` records the **system_admin bypass** (`iam/authz/authz.go` `Require`→`recordBypass`→`sink.RecordBypass`→`audit/.../writer.go RecordTx`, written **in the caller's tx**; the lock is xact-scoped, held to commit). An in-tx template-resolution read (`ensureTemplateArtifact` / template-version resolve → taxonomy `ProfileRepository.GetByCode`) opened its **own** connection+tx and called `authz.Require` again → tried to grab the **same** advisory lock on a different connection → blocked forever. Postgres cannot detect it (the holder is not waiting on a DB lock). **system_admin-only** — but admin is the only seeded dev user, so this blocked **100% of dev/admin CD-creates** (and every duplicate). Prod-breaking for any system_admin actor.

**Fix (no authz/audit-model change).** Hoist all authz-recording reads OUT of the lock-holding tx. CD-create auto path: `ensureTemplateArtifact` + `docInit.ResolveTemplateVersionID` now run **off-tx before** `s.runner.Do`; the pre-resolved template-version id is threaded into the in-tx `CloneTemplate` so the in-tx resolver **short-circuits** (no `GetDefaultTemplateVersionID`/`GetByCode` inside the tx). Same hoist applied in `CreateRevision`. `documents/application/service.go resolveTemplateVersionID` skips the default fetch when a concrete override id is supplied (domain `Resolve` already supports override-only input). ADR 0022 boundary intact: the advisory lock is untouched; `authz.Require`/`SeedTxIdentity` keep their `*sql.Tx` signature (deferred boundary #4). In-tx `CloneTemplate` readers (`GetPublishedVersion`, `LoadForSnapshot`) are plain SQL — acquire no advisory lock (statically confirmed).

**Runtime evidence.** `.\scripts\start-api.ps1 -Build` (Docker Postgres) → login admin (cookie) → `POST /api/v1/controlled-documents` (profile `po`, area `qualidade`, `Idempotency-Key`, trusted `Origin`) returned **409 `template.artifact_missing` in 83 ms** — previously a 60–90 s hang then 500 on the deadlock. `pg_locks` advisory count = **0** both before and after. Proves the observed deadlock site (`ensureTemplateArtifact`, now off-tx) returns fast with no lingering lock.

**Bounded defers (written triggers):**
- *Happy-path in-tx clone not runtime-exercised.* Seed gap, not a code defect: docgenv2 `template_versions` is empty and the seed artifact `system/templates/blank.docx` is absent from object storage; reconstructing the docgen pipeline is out of scope. Covered by unit tests (`go test -p 2 ./...` green incl. H-6b clone tests + `TestResolveTemplateVersionID_ShortCircuit`) + static lock-analysis. **Trigger:** seed a published template with a real docx artifact + matching docgenv2 version row, then runtime-exercise the in-tx clone + duplicate end-to-end.
- *409-before-403 ordering.* Off-tx `ensureTemplateArtifact` (409) now precedes the in-tx tier-2 `authz.Require(CapControlledDocumentCreate, area)` (403). A caller holding tier-1 create cap (passed the route PEP gate) but lacking area-scoped tier-2 now gets 409 instead of 403 — discloses template-artifact existence. Low severity (tier-1 PEP already gates create capability; artifact existence is operational-readiness, not secret). **Trigger:** ADR 0022 Phase 8 area-scope tightening — add an off-tx tier-2 pre-check to restore 403-before-409. Not inline-fixed: would re-introduce the off-tx taxonomy read the fix removed.
- *Redundant system_admin bypass-audit in CD-create.* Pre-existing (`repository/repository.go` `CreateDocumentTx` does `ctx = authz.WithCapCache(ctx)`, a pervasive 12×-in-file pattern, NOT introduced here) → the inner `authz.Require` re-records the bypass on the same tx. Harmless (advisory lock is session-re-entrant; same tx). **Trigger:** address when cap-cache context scoping is reworked.
