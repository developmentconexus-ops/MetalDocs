## 1. Target architecture (the "as-if-planned-from-day-one" North Star)

These are the patterns the codebase converges to. They come from what large SaaS document-control / workflow products (and our own accepted ADRs) already do. Each later finding maps to one of these.

- **N1 — Governed-artifact pair, separate modules, shared view layer.** `templates` (blueprint) and `documents` (instance) stay distinct bounded contexts. Convergence is frontend-only via `ArtifactViewModel` + pure shells + per-kind adapters. This is ALREADY DECIDED — ADR 0053 ("No module merge… convergence is a frontend view concern only") + ADR 0052 (manual versioning, shared `under_review` vocabulary). No new umbrella "Governed Artifact" ADR is needed; writing one would duplicate two Accepted ADRs. At most add an index cross-link.
- **N2 — One canonical route surface.** Exactly one route per state transition; OpenAPI is the only route truth; every mounted route exists in the spec and every spec route is mounted; generated `HandlerWithOptions` registration everywhere (the `controlleddocuments` pattern), with per-route middleware expressed via generated `Middlewares` closures.
- **N3 — One approval engine per aggregate, shared UX.** Documents keep the rich engine (instances→stages→signoffs, quorum/drift/SoD tripwire). Templates keep the inline version-row model. DECIDED by ADR 0053. What remains is closing the gaps *inside* each engine, not merging them.
- **N4 — One storage kernel.** ALREADY EXISTS: `internal/platform/objectstore/verified_store.go` (presign→upload→confirm-hash→pointer, tenant-prefix guard, size cap — implemented once). Remaining work is adopting its strongest commit pattern (documents' FOR-UPDATE reservation) in templates, not building a new kernel.
- **N5 — One schema family per aggregate.** Canonical: `public.templates_template(_version)`, `public.documents`, `public.controlled_documents`, `public.approval_*`, `metaldocs.*` for iam/audit/outbox/taxonomy platform tables. Everything else is legacy to be dropped after read-path cutover.
- **N6 — Uniform API ergonomics.** RFC 9457 problem+json on every error path; flat response bodies (ADR 0035) with generated DTOs end-to-end; Idempotency-Key on every mutating POST; cursor pagination as the standard list contract; ETag/If-Match OCC on every content-bearing write.
- **N7 — Defense-in-depth everywhere, symmetric.** Tier-1 route capability + tier-2 `authz.Require` in-tx + DB tripwire/RLS on EVERY mutating table and sensitive read — not just the approval cluster.
- **N8 — No fabricated data in product screens.** A screen renders real contract data or an honest empty/disabled state. Mock constants in shipped routes are defects.
- **N9 — Tests on one framework; legacy scaffolding deleted, not maintained** (ADR 0034 + standing policy).
