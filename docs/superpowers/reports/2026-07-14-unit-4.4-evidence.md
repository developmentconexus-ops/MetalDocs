`ComputeIdempotencyKey` "lost in M3" — restore derivation or ratify.

1. `ComputeIdempotencyKey` was **deliberately deleted**, not lost — commit `fed69283`

   justified it under CLAUDE.md's Global-Maximum rule; two-stage review APPROVE; contract-first
   regen declaring `Idempotency-Key` required).
3. Restoring `ComputeIdempotencyKey` would **re-introduce the F-D4 duplicate-instance bug** — a
   regression. The `:81` line reference is stale (pre-3.1-kernel-extraction path/line).

**Disposition:** no code change. Emitted `ESCALATION` to hub recommending a lightweight ADR to
formally record the "client Idempotency-Key + DB UNIQUE + platform middleware" decision so future
roadmap passes do not re-flag it as drift. The decision is already ratified-by-commit-and-review;

(the test-infra owner, `tests/integration/testdb/db.go`). Not fixed in this unit; no code touched
for it (cross-track ownership).

**Directly observed this unit (evidence for 4.3):**
1. *Leak* — the M3-class symptom reproduced: **340 orphan `metaldocs_test_*` databases** (1 template
   + 339 clones) had accumulated from prior killed/failed integration runs. Postgres was NOT in
   recovery (`pg_is_in_recovery()=f`), but the orphans bloat the harness. Cleared to 0 via in-container
   `psql` DROP DATABASE sweep (superuser `metaldocs_app`, ~2s/DB) before re-testing.
2. *Lifecycle race (distinct, still open)* — even on a **clean** DB (0 orphans), the scenarios
   package failed identically: the first test builds the content-addressed template
   (`prepareTemplateDatabase`, ~324s applying the full bootstrap) and passes, but the subsequent
   tests fail to clone it — `template database "metaldocs_test_template_f3a6738db7911839" does not
   exist (3D000)`. The template is created then disappears before the sibling clones run. This is a
   harness template-lifecycle/sweep race (`ensureTemplateDatabase` / `sweepStaleTemplates`), NOT
   orphan contamination and NOT a migration fault (no SQL error, assert never fired). It is the
   direct blocker that forced the direct-apply L1 proof above.

Track B owns the fix (`tests/integration/testdb`, plus removing the dead `grant_area_membership`
test + `e2e_seed.go` caller + the `metaldocsOwnedObjects` entry that 0307 renders stale). If 4.3
does not absorb it, it remains an open ROADMAP item for a future test-infra dispatch.
