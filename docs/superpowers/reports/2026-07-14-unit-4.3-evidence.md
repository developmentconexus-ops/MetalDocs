## 7. Parallel-track testdb template collision (§9 finding — flagged to hub)

The 3 tracks share postgres `:5433`. `testdb.Open` builds one content-addressed template per
schema **fingerprint**, then a "stale-template sweep" drops OTHER-fingerprint templates. When
tracks diverge (Track C adds migrations → different fingerprint), each track's sweep drops the
other's template → mutual deletion → `CREATE DATABASE ... TEMPLATE` fails `3D000 template
database ... does not exist`, or CREATE-DATABASE contention causes 10-min (614s) timeouts.

- **Same-fingerprint** concurrent runs (a track's own packages) are safe.
- **Divergent-fingerprint** cross-track runs mutually delete + contend.
- **Workaround used:** gate integration runs on a clear `pg_stat_activity` window.
- **Also observed:** killed runs skip `t.Cleanup` → orphan clone DBs (harmless — unique-named,
  don't block new CREATE; do NOT mass-DROP on the shared instance mid-run — the DROP storm
  contends on CheckpointDone and hangs live tracks).
- **Recommended durable fix (hub's call):** serialize cross-track integration runs, or give each
  track its own DB namespace / postgres port. Filed as a §9 DB-shape collision.
