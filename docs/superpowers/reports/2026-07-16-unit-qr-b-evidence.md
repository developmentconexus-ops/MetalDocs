## Root-cause statements

**F9.** `MaterializeJobRunner.Handle` (`internal/platform/worker/materialize_job_runner.go:63-107`) opens its tx and seeds ONLY the tenant RLS GUC via `authz.SeedTxTenant` (line 85). Its write — `WriteFinalDocxInTx` → `UPDATE public.documents SET final_docx_s3_key…` (`internal/modules/documents/infrastructure/snapshot_repository.go:117-131`) — hits `trg_require_cap_asserted` (baseline `db/baseline/0001_current_schema.sql:392-397`, UPDATE→`document.edit`), which requires either `metaldocs.asserted_caps` (set by `authz.Require`) or `metaldocs.bypass_authz='scheduler'` (set by `authz.BypassSystem`, only legal inside `authz.WithBackgroundBypass`). Neither is ever called in any async consumer → P0001 `ErrCapabilityNotAsserted` every attempt → `attempt_count` exhausts at 5 (`internal/platform/config/staging_outbox_worker.go:32`, `internal/platform/worker/service.go:100-141`) → `dead_lettered_at` set on `metaldocs.outbox_events` (`internal/platform/messaging/outbox/postgres/consumer.go:152-178`) → pipeline dead. GMR M3 F3.2 retrofitted the RLS/tenant seed into the consumers but the capability gate was never carried over. The sibling `PDFJobRunner` (`internal/platform/worker/pdf_job_runner.go:104-172`) writes `final_pdf_s3_key` to the same tripwire-guarded table with the same gap. NO replay/reset mechanism exists for dead-lettered outbox rows (grep-verified).

**F13.** Architecture truth (ADR 0015 verbatim: "A brief window (~seconds, normally) exists between `approved` status and the artifact being available. UI must represent this"; ADR 0009; `wiki/modules/render-fanout.md:78`) = PDF materialization is strictly ASYNC post-approval; publish is NOT gated on it and must not be (async-outbox invariant). No REQ/ADR states PDF is a publish precondition — target-architecture is silent. The honest-surfacing mechanism is what's broken: (a) `view_service.go:82-97` derives `pdf_status` and reads dead-letter state via `StagingOutboxRepository.ReadState(tenantID, docID)` — but passes the DOCUMENT id where the staging table keys on `revision_id` (suspected silent mismatch → forever-`pending`); (b) exhaustion of the FANOUT outbox (`metaldocs.outbox_events` dead-letter — the F9 failure site) is read by nothing, so the first hop dying is invisible to `pdf_status`; (c) FE `useDocumentPdfStatus.ts:36-43` fakes `failed` client-side after 60s, masking server truth; (d) `pdf_status` is already in the contract (`api/openapi/v1/openapi.yaml:5302-5311`, plain string in `ViewDocumentResponse`) and FE `PdfCanvas.tsx:28-43` already renders pending/failed — surfacing fix likely needs NO openapi shape change.
