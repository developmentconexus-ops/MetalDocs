## Slice 2 review notes
Production diff (migration 0303, `route_admin_service.go` insertRouteStageSelectors,
`postgres_approval_repository.go` LoadRoute selector read path) reviewed independently
by main session — APPROVE. Write path uses `INSERT ... SELECT ... JOIN` correlating
selectors to just-inserted stage ids by (route_id, stage_order) — no RETURNING
round-trip. Read path batch-loads via `pq.Array` + `= ANY($1)` ordered by
selector_order — no N+1. Migration is fail-closed (end-of-migration DO block RAISE
EXCEPTION if any stage lacks a selector), idempotent (WHERE NOT EXISTS), correct
schema_migrations ledger row.

Two **test-fixture** defects the implementer's own run never caught (it paused on a
slow monitor before verifying) — fixed by reviewer, production code untouched:
1. `WithRole("qms_admin")` → `chk_iam_user_roles_role_code` violation; valid set is
   {system_admin,approver,author,editor,viewer}. Changed to `system_admin` (matches
   sibling `route_admin_service_subject_integration_test.go`, carries CapRouteManage).
2. BackfillCoverage test asserted a **false property**: a stage seeded at test time
   postdates 0303's one-time backfill, so it can never be covered by it. Rewrote to
   execute 0303's verbatim backfill INSERT against the bare stage + assert idempotency
   — the property that actually validates the migration SQL run on real deploys.

Targeted `-run Selector|RouteStageSelector` → PASS (57s). Full-package run pending
(with raised `-timeout`; default 600s cap tipped by the 3 new tests, infra not logic).

  now runs ~850s, over Go's default 600s per-package `-timeout` cap. Slice 2's run

  `testdb.Open`. Not a unit-3.2 logic issue — pre-existing infra scaling. DEFER:
  surface to hub as a runner hardening item (add `-timeout` default). Verified green
  850s with the raised timeout this slice.
