# Unit 3.2 — M4 ActorSelector: unit design

**Date:** 2026-07-13
**Status:** unit-level elaboration of the operator-ratified milestone spec §6 (B1–B6),
`docs/superpowers/specs/2026-07-08-approval-workflow-coherence-design.md:207-249`. Stays WITHIN that
ratified scope — any deviation surfaces to the hub as `BLOCKED`, never silent adaptation.
**System-impact gate:** `docs/superpowers/analysis/2026-07-13-unit-3.2-actor-selector-system-impact.md` (🟡 Yellow).
**Owning module:** `approval` (module 15, extracted kernel, ADR 0082). Subject-generic — serves documents AND templates from one implementation.

---

## 1. Goal

Replace the flat per-stage `RequiredRole`/`AreaCode` assignment with a BPMN-aligned **discriminated
union of actor selectors**. One stage may carry several selectors; the resolver unions their pools.
The flat route-config columns are retired after a verified backfill (single source of truth). The
instance-side `*_snapshot` audit columns and every downstream semantic (snapshot-at-submit, quorum,
drift, SoD, delegation, freeze) are **untouched**.

## 2. Selector union (B1 domain)

`Stage.Selectors []ActorSelector` **replaces** `Stage.RequiredRole` + `Stage.AreaCode` as the
resolution input. `Stage.RequiredCapability` stays (it is the signoff capability pin, orthogonal to
*who* is in the pool).

| `kind` | Fields (non-null) | Resolves to | Drift class (ADR 0084) |
|---|---|---|---|
| `named_user` | `user_id` | exactly that user (tenant-checked) | **exempt** — fixed identity never drifts |
| `role_in_fixed_area` | `role`, `area_code` | role × fixed area (current model, preserved) | **pool** — re-evaluated per stage `DriftPolicy` |
| `role_in_document_area` | `role` | role × the *subject's* area (area follows the document/template) | **pool** — re-evaluated per stage `DriftPolicy` |
| `submit_choice` | `role`, `area_code` (constraint scope) | at submit: the caller-chosen actor(s), each validated to satisfy `role`×`area_code` | **exempt post-submit** — the chosen set is frozen like `named_user` |

Domain `ActorSelector.Validate()` enforces per-kind field presence/absence (mirrors the DB CHECK).
`Route.Validate` gains: **≥1 selector per stage**; `submit_choice` requires its constraint fields;
quorum-consistent-with-minimum-resolvable-pool where statically knowable (pool-selector counts stay a
submit-time `ErrEmptyEligiblePool` check, as today — not statically computable).

## 3. DB (B2)

New child table `approval_route_stage_selectors`:

```
id             uuid pk
tenant_id      text  not null            -- multi-tenant predicate
route_stage_id uuid  not null references approval_route_stages(id) on delete cascade
selector_order int   not null            -- stable UI ordering within the stage
kind           text  not null
user_id        text  null
role           text  null
area_code      text  null
-- CHECK kind IN ('named_user','role_in_fixed_area','role_in_document_area','submit_choice')
-- CHECK per kind:
--   named_user            : user_id NOT NULL AND role IS NULL AND area_code IS NULL
--   role_in_fixed_area    : role NOT NULL AND area_code NOT NULL AND user_id IS NULL
--   role_in_document_area : role NOT NULL AND area_code IS NULL AND user_id IS NULL
--   submit_choice         : role NOT NULL AND area_code NOT NULL AND user_id IS NULL
unique (route_stage_id, selector_order)
```

DB enforces the per-selector invariants (invariant 5) — app `Validate` is the friendly first line.
No tripwire needed: this is route *config* written on the `route.admin`-gated route-admin path, not
the regulated `approval_instances`/`approval_signoffs` write path (whose tripwires are unchanged).

**Migration sequence (expand → backfill → contract):**
- **0303_approval_route_stage_selectors.sql** — CREATE table + CHECKs; **backfill** one
  `role_in_fixed_area(required_role, area_code)` selector for every existing `approval_route_stages`
  row; end-of-migration **verification query** asserting every stage has ≥1 selector (fail the
  migration otherwise). Flat columns retained.
- **0304_drop_route_stage_flat_assignment.sql** — the contract step: `DROP COLUMN required_role`,
  `DROP COLUMN area_code` from `approval_route_stages`. Lands as the FINAL backend slice, only after
  the resolver/route-admin/submit code is fully cut over to selectors AND the old-vs-new resolver
  **parity test** on existing routes is green. Instance-side `*_snapshot` columns are NOT dropped
  (audit freeze — separate concern).

## 4. Resolver (B3)

`ResolveEligibleActors` changes signature from `(…, areaCode, requiredRole)` to take the stage's
`[]ActorSelector` (+ the subject area for `role_in_document_area`). Per selector:
- `named_user` → `{user_id}` after tenant/existence check.
- `role_in_fixed_area` → the **existing** role×area query, unchanged.
- `role_in_document_area` → same query with `area_code` = the subject's area (already resolved on the
  submit path via the existing `cdRead` port, `submit_service.go:94` — no new cross-module edge).
- `submit_choice` → contributes no pool at snapshot time from the route alone; at submit the
  caller-chosen actors are validated server-side against `role`×`area_code` and unioned in.

Result = **union + dedup** of per-selector pools. Snapshot `eligible_actor_ids` + quorum/drift/SoD/
delegation/freeze downstream are byte-for-byte unchanged. `role_in_fixed_area`-only stages (the
backfilled existing routes) MUST resolve to the identical pool the flat model produced — that is the
parity test.

## 5. Contract (B4)

- **Route GET/PUT DTOs** gain `selectors: ActorSelector[]` per stage; `required_role`/`area_code`
  removed from the stage request/response once 0304 lands. `ActorSelector` is a **flat** schema
  `{ kind: enum, user_id?, role?, area_code? }` — the codebase has zero `oneOf`/`discriminator`
  (grep-verified); flat aligns ADR 0035 and oapi-codegen ergonomics. Validation lives in domain + DB.
- **Submit request DTO** (`/documents/{id}/submit` and templates submit) gains optional
  `chosen_actors: [{ stage_order, user_ids[] }]`. Required only when a stage has a `submit_choice`
  selector; a `submit_choice` stage with no matching choice → `422` fail-closed
  (`ErrSubmitChoiceRequired`); a chosen user violating the constraint → `422`
  (`ErrSubmitChoiceConstraintViolated`).
- Contract-first: edit `api/openapi/v1/openapi.yaml` + module `cfg.yaml`, regenerate Go
  (`go generate`) and FE (`pnpm gen:api`). **Never** hand-edit `api.gen.go`.

## 6. FE (B5)

- `RouteEditorDialog` selector builder — extends the **StageActorSlot** extension slot route-builder
  v2 deliberately left (replaces raw role/area text fields). Per stage: add/remove/reorder selectors,
  each a kind-picker + kind-appropriate fields (user autocomplete for `named_user`; role+area for
  `role_in_fixed_area`; role for `role_in_document_area`; role+area for `submit_choice`).
- **Submit dialog picker** — when the resolved route has a `submit_choice` stage, the submit dialog
  renders a candidate picker (constrained to the stage's role×area) and sends `chosen_actors`.
- FE typecheck: `pnpm exec tsc --noEmit -p tsconfig.build.json`. No `pnpm install` (symlinked
  node_modules).

## 7. ADR 0084 (mandatory — spec §8.4)

**ActorSelector model** — records: union-of-selectors as the stage-assignment standard
(BPMN candidateUsers/candidateGroups/assignee alignment); the four selector kinds; **drift semantics
per selector class** (pool kinds re-evaluate per `DriftPolicy`, `named_user` + post-submit
`submit_choice` exempt); the retirement of the flat `required_role`/`area_code` route-config columns
(single source of truth) via the expand/backfill/contract sequence; the non-goals from spec §7
(dynamic-rule selectors, DAG stages — reopen triggers named there).

## 8. Slice plan (vertical, PR-sized, each green before the next)

1. **Domain** — `ActorSelector` + `SelectorKind` + `Validate`; `Stage.Selectors`; `Route.Validate`
   selector rules. Unit tests per kind + combinations. (flat columns still present on the struct)
2. **DB expand + backfill** — migration 0303 + repo read/write of selectors; backfill verification
   query; testdb integration: round-trip + CHECK rejection per kind + backfill coverage.
3. **Resolver** — selector-union `ResolveEligibleActors`; real-DB parity test (old flat vs new
   selector) on backfilled routes; union/dedup tests.
4. **Contract — route admin** — OpenAPI selectors on route GET/PUT + regen + route-admin
   service/handler wiring; contract parity + cross-tenant 404.
5. **Contract — submit choice** — OpenAPI `chosen_actors` + regen + submit-side validation
   (`ErrSubmitChoiceRequired`/`Constraint`); real-DB submit_choice accept/reject tests.
6. **Contract step — drop flat columns** — migration 0304 + remove `RequiredRole`/`AreaCode` from
   `Stage` + DTOs; full build/suite green (parity from slice 3 must precede this).
7. **FE — RouteEditorDialog selector builder** — StageActorSlot → selector builder; vitest.
8. **FE — submit picker** — submit dialog candidate picker; vitest.
9. **ADR 0084 + wiki sync** — write ADR; refresh `wiki/modules/approval.md` (§5.2/§8) `Last verified`.

## 9. Non-goals (spec §7 — written refusals, not deferred)

Dynamic-rule selectors (manager-of, field-driven) and W12 parallel/DAG stages remain **out** with the
reopen triggers spec §7 names. Rebuilding the worklist is out (C3/C5 shipped).
