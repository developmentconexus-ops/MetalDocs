# Plan 8 — OpenAPI / Contract-First Completion

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **Step 0 gate:** Do not execute module migrations until the route truth tables and target-state decisions in this plan have been validated against runtime code, OpenAPI, generated interfaces, and module wiki docs.

**Goal:** Every HTTP route in `api/openapi/v1/openapi.yaml` covered by an operationId + typed schema. Codegen wired for all 6 affected modules. No raw `mux.HandleFunc` surviving for any migrated module.

**Architecture:** Spec-first per ADR 0012. Each module gets `internal/modules/<x>/api/{cfg.yaml, gen.go, api.gen.go}`. Handler struct implements the generated `ServerInterface`; `ServerInterfaceWrapper` replaces raw mux registrations. Approach: add delegation methods (public methods on Handler calling existing private methods) — do NOT rename private handler methods or move business logic.

**Tech Stack:** Go 1.22+, oapi-codegen v2 (`github.com/oapi-codegen/oapi-codegen/v2 v2.7.0`), OpenAPI 3.0.3, `GOFLAGS=-mod=mod go generate`, openapi-typescript v7 (frontend).

**Prerequisite check:** Plan 7 DONE (2026-05-12). All error responses use `application/problem+json`. Registry 422 `template_invalid` live. Taxonomy RFC 9457 via cascade. ✓

**Execution model:**
- **Codex (`codex:rescue`):** spec authoring, handler wiring, ServerInterface implementations.
- **Sonnet/Haiku:** `go test`, `go build`, commits.
- **Opus:** ONE grouped review after ALL 6 module PRs land (not per-PR).

**STOP rules:**
- If any handler method signature does not match what the spec would generate, STOP — report the mismatch, do not guess.
- If a route listed in the spec has no corresponding handler in the codebase, STOP — do not add a handler stub.
- Taxonomy spec: derive every field name from the domain structs and route handler code — no invented fields.

## Route Truth Gate

Before any module migration task:

- Build the runtime route table from actual `mux.HandleFunc` / `mux.Handle` registrations.
- Map each runtime route to:
  - owning file
  - owning handler method
  - OpenAPI path
  - OpenAPI tag
  - `operationId`
  - generated `ServerInterface` method name and signature
  - module wiki/tech-debt note

Required stop conditions:

- runtime route has no real handler
- spec route has no runtime owner
- generated signature differs from the plan's expected method
- path parameter name differs between runtime and spec
- product ownership is ambiguous across modules

### Documents route truth focus

Validate and decide before implementation:

- whether `POST /api/v2/documents` remains part of the public contract or is retired in favor of registry-owned atomic create
- whether document export remains owned by `ExportHandler` or is consolidated into a single module HTTP contract
- whether checkpoint restore uses `{version}` or `{versionNum}` as the canonical path parameter name
- whether generated `ServerInterface` methods require typed path/query params that differ from the delegation examples

- `templates_v2`: complete the spec for all runtime routes before declaring wrapper-only migration complete
- `approval`: author spec from actual 16 runtime routes before codegen bootstrap
- `taxonomy`: author spec from actual 16 runtime routes before codegen bootstrap
