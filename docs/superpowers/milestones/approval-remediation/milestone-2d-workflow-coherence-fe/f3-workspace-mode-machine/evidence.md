> **Contract:** `spec.md` (consumer contract + Validation Gate this proves against).

## What was implemented

By outcome (producer matches the consumer contract — the screen/DecisionFooter switch on one
`WorkspaceMode`):

- **New pure selector** `frontend/apps/web/src/features/approval/lib/workspaceMode.ts`:
  `WorkspaceMode` type, subject-agnostic `deriveStageMode(stageKind, eligible)` (no document arg —
  survives M3 kernel/templates reuse), and `deriveWorkspaceMode(doc, instance, viewer)`. Reads server
  facts only (`viewer.eligible_for_active_stage`, ADR 0078); never re-derives eligibility.
- **`TRANSITION_POLICY` shrunk** (`approvalWorkflow.ts`): `signoff` removed from `TransitionPolicy.actions`
  type + all 9 entries. `cancelInstance` + `publishOrSchedule` (document-lifecycle) stay.
- **`signoffOffered` rewired** (`useDocumentApprovalArtifact.ts`): the status-based `policy.actions.signoff`
  gate (the M2c defect — offered signoff regardless of stage kind/eligibility → `412
  content_hash_mismatch`) replaced with `deriveWorkspaceMode(...) === 'approving'` (an active approval
  stage the viewer is eligible for). `instance` is a direct alias of the generated by-document response,
  so `instance.viewer` is typed + always present (F2d.1).
- **Cockpit test updated to the corrected contract** (`useDocumentApprovalArtifact.test.tsx`): added the
  now-required `viewer`/`verdicts` to the fixture; the three offered-decision tests use a
  `makeApprovingInstance()` (active approval stage + eligible viewer) instead of asserting signoff is
  offered merely because status is `under_review`.

Committed at F2d.3 close (review clean).
