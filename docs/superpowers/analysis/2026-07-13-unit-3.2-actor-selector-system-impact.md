# System-impact analysis — Unit 3.2 M4 ActorSelector (BPMN-aligned selector union)

**Date:** 2026-07-13
**Intent (one line):** Replace the flat `RequiredRole`/`AreaCode` stage assignment with a BPMN-aligned discriminated union of actor selectors (`approval_route_stage_selectors` child table + resolver union + contract + FE builder + submit-choice picker) in the extracted subject-generic approval kernel.
**Work type:** feature
**Author:** developing-new-work skill
**Verdict:** 🟡 Yellow *(see §10 — ADR #4 required, backfill-drift risk carried)*

> Governing spec: `docs/superpowers/specs/2026-07-08-approval-workflow-coherence-design.md:207-249` (§6 Milestone B, B1–B6). ROADMAP 3.2.

## 1. Classify & own

- **Work type:** feature (new child table + selector union inside an existing module; no new bounded context).
- **Owning module(s):** `approval` (top-level module 15, post-M3 kernel extraction, ADR 0082). It owns route/stage config (`domain/route.go` `Stage`), eligibility resolution (`ResolveEligibleActors`, `submit_service.go:230`), the route-admin contract, and the submit path. Selectors are a property of `Stage` — they live here.
- **Explicitly NOT owning:**
  - `taxonomy` — owns governance class / `RoutePolicy`; unrelated to *who* resolves per stage. Not touched by selectors.
  - `iam` — owns roles/areas/capabilities. Selectors *reference* role codes and area codes, but iam does not own the selector union; approval already resolves role×area → actor ids via its repo query. No iam surface change.
  - `documents`/`templates` — subjects the kernel governs. Selectors are subject-generic; `role_in_document_area` follows the subject's area, which the kernel already reads via the existing `cdRead` area port (`resolveSubjectAreaCode`, `submit_service.go:94`). No new reach into either module.
- **Cross-module edges (with direction):** `approval → taxonomy` (existing `ProfilePolicyReader`, unchanged) and `approval → {documents,templates}` area read via the existing published `cdRead` port (unchanged). **No new cross-module edge introduced.** `role_in_document_area` reuses the area code the submit path already resolves.
- **Ambiguity?** None. AS-3 not triggered.

## 2. Foundation verdict

- **Base you'd build on:** the extracted `internal/modules/approval` kernel — `Stage{RequiredRole, RequiredCapability, AreaCode, ...}`, `Route.Validate(policy)`, `ResolveEligibleActors(ctx, tx, tenantID, areaCode, requiredRole)`, per-stage `*_snapshot` columns frozen at submit. Subject-generic `(subject_kind, subject_key)` since M3.
- **Sound, or legacy/patch/workaround?** **Sound.** The kernel is Grade-A, freshly extracted (ADR 0082), and route-builder v2 deliberately left the StageActorSlot as a clean extension slot for exactly this unit (HARNESS §3 names it a named consumer, not YAGNI). Building the selector union here is *completing* the ratified design, not patching around it.
- **Global-maximum note:** the flat `RequiredRole`+`AreaCode` pair is the *narrow* current model — spec B1 supersedes it with the union, and B2 **retires** the two flat columns after backfill so there is no dual source of truth. This is the global maximum (single normalized child table, DB-enforced per-type CHECKs) rather than bolting selectors on *alongside* the flat fields. The `*_snapshot` columns on the instance stay (audit freeze — separate concern from route config). No AS-2. The one carried trade-off is the backfill migration (§7).

## 4. Capability wiring

**N/A** — no new IAM capability. The selector union is route configuration data; the existing `route.admin` (route writes) and `doc.submit` (submit) capabilities cover every new surface. `submit_choice` validation ("chosen actor satisfies the stage's role/area constraint") is a *domain* check inside the already-authz'd submit tx, not a new capability boundary.

## 5. Module wiring

**N/A** — feature inside the existing `approval` module (module 15). No new bounded context; ADR 0082 already birthed the kernel.

## 6. Frameworks to reuse, not reinvent

- `TxRunner` (`Do`) — selector persistence + resolution ride the existing route-admin and submit tx boundaries; no new `*sql.DB`.
- `tenant.FromContext` — tenant id for the new table's predicate.
- `authz.SeedTxIdentity` / `authz.Require` — unchanged; selectors add no new authz path.
- `problem.New` / `problem.Write` — new domain sentinels (`ErrStageNoSelector`, `ErrSubmitChoiceConstraintViolated`, `ErrSubmitChoiceRequired`, etc.) map to RFC 9457 codes.
- `contracts.Decode` (strictjson) — route + submit DTO decode.
- `testdb.Open` + factory builders — resolver union / backfill-parity / submit-choice-rejection integration tests (`//go:build integration`).
- Existing `cdRead` area port — `role_in_document_area` pool resolution.

No hand-rolled equivalents. The resolver is a union of the *same* per-selector query the flat model already runs — not a new query framework.

## 7. Contract & data

- **OpenAPI-first:** add `selectors: []ActorSelector` (discriminated by `kind`) to route GET/PUT DTOs; add optional `chosen_actors` (per-stage) to the submit request DTO. New schemas: `ActorSelector` (oneOf/discriminator by `kind` ∈ {`named_user`, `role_in_fixed_area`, `role_in_document_area`, `submit_choice`}). Regenerate Go + FE types (`pnpm gen:api`).
- **Migration (expand → backfill → contract):**
  - `0303_approval_route_stage_selectors.sql` — create child table (`id`, `tenant_id`, `route_stage_id` FK, `kind`, `user_id?`, `role?`, `area_code?`, ordering), per-`kind` CHECK constraints, tenant predicate support. **Backfill**: every existing `approval_route_stages` row → one `role_in_fixed_area(required_role, area_code)` selector. Verification query asserts 1:1 backfill coverage (no orphaned stage).
  - Contract step (same migration or a paired `0304`): retire `required_role` / `area_code` from `approval_route_stages` **after** backfill parity is proven (spec B2: no dual source of truth). Retire only the *route-config* columns — the instance-side `*_snapshot` audit columns stay.
  - **Parity test** (spec §10 risk): old-resolver-vs-new-resolver on existing routes must produce identical eligible pools before the contract step lands.
- **Destructive change?** Yes — column retirement. Handled by the expand/backfill/contract sequence; the live contract is never broken in one step. This is the primary carried risk (§10).

## 10. Verdict & locked constraints

- **Verdict:** 🟡 **Yellow** — proceed to brainstorming; the design carries a mandatory ADR and one named data-migration risk.
- **Open hard-stops:** none. AS-1 / AS-2 / AS-3 all clear (sound foundation, no invariant violation, unambiguous owner).
- **Locked constraints handed to brainstorming:**
  1. **ADR 0084 (ActorSelector model)** is mandatory (spec §8.4) — union-of-selectors standard + drift-per-selector-class semantics + column-retirement rationale.
  2. **Single source of truth** — the flat `required_role`/`area_code` route-config columns are **retired** after backfill (spec B2). No selectors-*alongside*-flat-fields dual model. Instance `*_snapshot` audit columns are a separate concern and stay.
  3. **Expand → backfill → contract** migration with a 1:1 backfill verification query AND an old-vs-new resolver **parity test** on existing routes before the contract step lands (spec §10 risk).
  4. **Snapshot-at-submit preserved** — eligibility freezes at submit exactly as today; the resolver change swaps the *input* (selectors instead of flat role/area) but the frozen `eligible_actor_ids` + quorum/drift/SoD/delegation/freeze semantics are **untouched** (spec B3).
  5. **`submit_choice` validated server-side** at submit — the chosen user must satisfy the stage's role/area constraint; never trust the client's choice (H-PRE-1: this read stays in-tx as today, no authz-recording read inside a lock-holding tx).
  6. **DB enforces per-selector invariants** — CHECK constraints per `kind`, not app-only validation.
  7. **Subject-generic** — the selector union serves documents AND templates from one kernel implementation (spec B: "built once, serving documents AND templates"). Do not re-couple to `documents`.
  8. **Contract-first / no `api.gen.go` hand-edits**; new tests on `testdb` factory.
