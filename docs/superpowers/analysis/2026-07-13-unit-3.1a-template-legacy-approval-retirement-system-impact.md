# System-impact analysis — Unit 3.1a: template legacy-approval retirement

**Date:** 2026-07-13
**Intent (one line):** Retire the legacy role-based template-approval path, leaving the subject-generic approval kernel (ADR 0082) as the sole path for template-version approval.
**Work type:** feature (retirement / capability removal within the existing `templates` module; no new module)
**Author:** developing-new-work skill (unit 3.1a agent, P0 gate)
**Verdict:** 🟡 Yellow  *(see §10)*

> This is a RETIREMENT executing an already-ratified design (ADR 0082 §Transitional coexistence + operator Option A, 2026-07-12). The gate is run to confirm no invariant is violated and to lock the risks the design must honor — not to re-open the decision.

---

## 1. Classify & own
*(CLAUDE.md Orientation rule)*

- **Work type:** feature. It deletes a legacy path and migrates two callers onto capabilities; it does not birth a module.
- **Owning module(s):**
  - `templates` — owns `CreateTemplate`, `PublishTemplateVersion`, the 4 legacy approval routes/handlers, `domain.ApprovalConfig`, `templates_approval_config`, and the FE approval surface. Primary owner.
  - `iam` — owns capability `CapTemplateReview` (removed) + the capability registry/coherence guards.
  - `templates` FE (`frontend/apps/web/src/features/templates`) — owns `TemplateApprovalRoute.tsx` / `TemplateEditorPage.tsx`, rebuilt onto the kernel routes.
- **Explicitly NOT owning:**
  - `internal/modules/approval` (the kernel) — NOT modified. Its published surface (`TemplateSubmitService`, `DecisionService`) already exists from 3.1/M3 and has zero FE consumers. This unit *consumes* it, does not change it.
  - `documents` — untouched; it already uses the kernel.
- **Cross-module edges (direction: A → B = A depends on B):**
  - `templates(FE) → templates(api)` kernel routes `POST .../submit-for-approval` + `.../signoff` (contract, already exists).
  - `templates(delivery/http) → approval(application)` via the existing thin adapters in `routes_approval_kernel.go` (published surface only — ADR 0082 boundary allow-list). No new edge; the legacy deletion *reduces* templates' internal surface.
  - `templates(application) → iam/authz` `authz.Require` tier-2 (already the pattern in `create.go`). Migrating create/publish off roles keeps this edge, drops the role-binding reads.
- **Ambiguity?** None. Owning module is unambiguous → no AS-3.

## 2. Foundation verdict
*(Global-Maximum rule)*

- **Base you'd build on:** two parallel template-approval implementations coexisting since M3 — (1) the legacy role-based path (`templates_approval_config`, `domain.ApprovalConfig`, `CheckSegregation`, `RoleBindingFor`, `Pending{Reviewer,Approver}Role`, 4 routes) and (2) the subject-generic kernel (ADR 0082).
- **Sound, or legacy/patch/workaround?** The legacy path is explicitly **legacy** — ADR 0082 names it a transitional coexistence to be retired, and the ratified model requires the *same* eQMS kernel (SoD/quorum/delegation/e-signature/state-machine) for template versions as for documents. Two parallel approval implementations is precisely the local maximum ADR 0072 warned against.
- **Global-maximum structure:** kernel-only (one approval implementation, subject-discriminated). This unit **deletes** the local maximum rather than optimizing inside it — it is the correct global-max move, and it is what ADR 0082 already ratified. **No AS-2:** we are not improving on a bad base; we are removing it.
- **GM fork:** none. There is exactly one ratified target (kernel-only). The only sequencing choice — do (a) migrate create/publish, (b) FE rebuild, (c) delete — before dropping the shared table is forced by the fact that create+publish still consume `templates_approval_config` until (a). That is a dependency ordering, not competing structures. No fork record needed.

## 4. Capability wiring
*(REMOVING a capability — the 10-touchpoint walk run in reverse for `CapTemplateReview`)*

`CapTemplateReview` becomes functionally unreferenced once the legacy `review` route + handler + tier-1 rule + tier-2 check are deleted. Reverse-walk:

1. **const + `validCapabilities`** — remove the `CapTemplateReview` const and its `validCapabilities` entry (`internal/modules/iam/domain/model.go`).
2. **scope classify** — remove its `ScopeTenant/ScopeArea` classification row (`capability_scope.go`). Guard `TestEveryCapabilityClassified` must stay green (no orphan).
3. **tier-1 route→cap** — the `POST .../review` route is deleted, so its `permissions.go` row is deleted with it. (No dangling rule pointing at a removed cap; no route left unmapped.)
4. **tier-2 in-tx** — the legacy `Review` handler/service `authz.Require(CapTemplateReview,…)` call is deleted with the handler.
5. **seed grants** — remove `CapTemplateReview` grants from `db/reference-data/0001_product_reference_data.sql` (and any role seed). Investigator to confirm exact rows.
6. **DB tripwire (`ck_cap_format`/`ck_cap_not_legacy`)** — no change needed: these validate *format*, not membership; a removed cap simply stops appearing. No arm keys on `CapTemplateReview`.
7. **guard tests green** — `TestEveryCapabilityClassified`, `TestAreaGradeCapabilitySet` must remain green after removal.
8. **`TestCapabilityRegistrySize`** — **DECREMENT** `const want` by 1 (the one mandatory manual edit; reverse of the "bump" rule). Targeted-verify the current count before editing.
9. **CI capability-coherence (REQ-AUTHZ-5, 5-surface)** — const/classify/tier-1/seed/test must all agree post-removal; the coherence lint is the backstop that catches a missed surface. Also keep `tripwire_caps_test.go` truthful (memory `dev-seed-template-approval-authz-gap`): arms are regenerated via the registry path (GMR M2), **never hand-edited**.
10. **H-PRE-1** — N/A (removal adds no authz-recording read inside a lock-holding tx).

**Locked constraint:** removing `CapTemplateReview` ⇒ decrement `TestCapabilityRegistrySize`, keep the 5-surface coherence lint + `tripwire_caps_test.go` green, regenerate arms via the registry path.

## 7. Contract & data

- **OpenAPI-first:** DELETE 4 operations from `api/openapi/v1/openapi.yaml` — `submitTemplateVersion`, `reviewTemplateVersion`, `approveTemplateVersion`, `upsertTemplateApprovalConfig` (+ any request/response schema components used *only* by them; keep shared ones). Regenerate the templates api package. Kernel ops `submitTemplateVersionForApproval` + `signoffTemplateVersion` **stay**. api-lint PARITY/DRIFT must be green (Go↔SQL↔DB).
- **Migration:** `db/migrations/0301_drop_templates_approval_config.sql` — forward-only, **pre-drop emptiness assert** (`RAISE EXCEPTION` if `SELECT EXISTS(SELECT 1 FROM templates_approval_config)`), then `DROP TABLE templates_approval_config`. Confirm no FK/trigger references it first (investigator SECTION G). No `tenant_id` change elsewhere.
- **Destructive change (expand/contract):** the whole unit IS the contract step of an expand→contract already begun in M3 (kernel routes = expand; this = contract). Sequenced (a)→(b)→(c) so the table is emptied of dependence before the drop: create+publish stop writing/reading it in (a); (c) drops it. The emptiness assert is the safety net that the contract step never lands on live data.

## 10. Verdict & locked constraints

- **Verdict:** 🟡 **Yellow** — proceed. The design is already operator-ratified (ADR 0082 + Option A); no hard-stop is open. Yellow (not Green) because a capability removal carries the mandatory registry-count edit + 5-surface coherence risk, and route deletion carries a contract-parity risk — both must be carried into the plan as locked constraints and machine-verified.
- **Open hard-stops:** AS-1 none · AS-2 none · AS-3 none.
- **Locked constraints handed to the plan:**
  1. **Sequence is mandatory:** (a) migrate `CreateTemplate` + `PublishTemplateVersion` off the role model → (b) rebuild FE onto kernel routes → (c) delete legacy + DROP table. The table cannot drop until (a) removes create/publish's dependence on it.
  2. **Capability removal:** `CapTemplateReview` removed across all 5 coherence surfaces; **decrement** `TestCapabilityRegistrySize`; keep `TestEveryCapabilityClassified` + `tripwire_caps_test.go` green; regenerate tripwire arms via the registry path, **never hand-edit** (`arms.go` / `dev-seed-template-approval-authz-gap`).
  3. **Contract-first deletion:** remove the 4 legacy ops from OpenAPI + regenerate; never hand-edit `api.gen.go`; api-lint PARITY/DRIFT green.
  4. **Forward-only DROP with pre-drop emptiness assert** (fail loud); confirm no FK/trigger dependents first.
  5. **Kernel untouched:** do not modify `internal/modules/approval`; consume its published surface only (boundary guard green).
  6. **Legacy tests deleted, guard tests kept** (legacy-test rule); every new test on the canonical `testdb` framework.
  7. **Verify the whole ladder from clean state after each RED**; zero new integration failures beyond the 9-test accepted baseline.
