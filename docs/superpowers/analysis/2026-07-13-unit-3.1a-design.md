## 1. Global-maximum judgment (carried from P0 §2)

The legacy role-based template-approval path is a **named local maximum**: a second, parallel approval implementation that ADR 0072 explicitly warned against and ADR 0082 ratified for retirement. The global maximum is **kernel-only** — one subject-discriminated approval implementation (`internal/modules/approval`) serving both `documents` and `templates`. This unit **deletes** the local maximum; it does not optimize inside it. No competing structure exists → no GM fork.

## 2. Why the sequence is mandatory (a) → (b) → (c)

`templates_approval_config` + `domain.ApprovalConfig` + the role fields are shared between the 4 legacy routes AND two non-legacy callers (`CreateTemplate` seeds roles + writes the config table; `PublishTemplateVersion` does role-SoD). Therefore:

- **(a) first** — migrate `CreateTemplate` (stop seeding roles) + `PublishTemplateVersion` (kernel-conformant completion, drop role-SoD) off the role model. Until this lands, the table/type are load-bearing and cannot be dropped.
- **(b) second** — rebuild the FE onto the kernel routes (`/submit-for-approval` + `/signoff`). The legacy backend routes must stay live until the FE no longer calls them, or the UI 404s.
- **(c) last** — delete the legacy backend path (routes + handlers + service methods + domain + repo methods + tests) and DROP the table behind a pre-drop emptiness assert; clean up `CapTemplateReview` + `domain.ApprovalConfig` orphans.

Reversing the order strands create/publish (drop-first) or 404s the UI (delete-routes-first).

## 3. Slice strategy (vertical, PR-sized, revertable; commit per green slice)

Each slice: **failing test first** (canonical `testdb` for DB integration) → implement to green (dispatched **sonnet** subagent, ONE slice per dispatch) → **independent sonnet reviewer** (cavecrew-reviewer / frontend reviewer) two-stage (code + domain/authz/contract) BEFORE the next slice. Mechanical-only sweeps → **haiku**. I (Opus) write only ≤10-line trivial glue inline.

**Provisional slice cut (file lists finalized from the inventory appendix §7):**

- **S1 — (a) `CreateTemplate` off role-seeding.** Stop seeding reviewer/approver *roles* + stop writing `templates_approval_config` at create. - **S3 — (b) FE rebuild onto kernel routes.** `TemplateApprovalRoute.tsx` / `TemplateEditorPage.tsx` call `POST .../submit-for-approval` + `.../signoff` via the generated `openapi-fetch` client (`lib/api-types/`, never hand-edited) + react-query hooks under `features/templates/api/`, invalidating the correct `QK` keys. Slice ordering/deps: S1 ⟂ S2 (both (a), independent, can parallelize with 2 dispatches but each reviewed before S4). - **R2 (S5):** is `template.review` load-bearing in the `enforce_capability_asserted()` `templates_template_version` tripwire branch for a KEPT write (kernel signoff / publish)? (investigator SECTION J.) If yes → the branch needs a forward migration to accept the kept path's asserted cap; removing `CapTemplateReview` blind would brick a kept write. If the kernel signoff asserts `template.approve` and the branch already accepts it, we're clear.
- **R3 (S3):** FE toolchain (`fe-node-modules-junction-drift`) may block vitest/vite. Never `pnpm install` in the symlinked tree; REQUEST to hub if blocked.
