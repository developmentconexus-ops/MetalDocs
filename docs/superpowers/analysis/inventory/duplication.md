## The five heaviest, with detail

**DUP-01 (dual UserIDFromContext).** Two helpers of the same conceptual purpose exist with opposite failure semantics — one silently returns `""` on a missing principal, the other fails closed with `(string, bool)`. The comment on the newer one explicitly says it exists because the old one "pushes that check onto each caller," yet 17 call sites across 7 modules still call the old one directly, including delivery/http and application layers that make authorization-adjacent decisions (`taxonomy/infrastructure/authz_guc.go:27`, `tokens/application/service.go:182/207/232`). This is duplication with a documented severity gradient: a caller that forgets the trim/empty check on the bare version treats an anonymous caller as a valid (empty-string) actor. This is the shape of hazard the wrapper was built to close, but the migration was never finished.

**DUP-04 (Tx/non-Tx hand-copies).** 20 method-name pairs across `documents`, `templates`, `controlleddocuments`, `taxonomy`, `tokens`, `approval` infrastructure repos duplicate identical SQL text and, in the documents case, identical `authz.Require` calls between the transactional and non-transactional variant. The non-Tx version does not call the Tx version with a fresh transaction — it is a hand-copy. Any future change to the SQL, the authz capability required, or the error mapping has to be made twice by hand with nothing forcing agreement; documents' `UpdateDocumentName`/`UpdateDocumentNameTx` already required the exact same `authz.Require(ctx, ..., iamdomain.CapDocumentEdit, docArea)` line to be present in both, which is the same "hand-synced enumeration" shape as ME-01, just at the function-body scale rather than the declaration scale.

**DUP-02 (15+ collided sentinel-error names).** Go gives no namespace collision warning across packages, so `ErrNotFound`, `ErrForbidden`, `ErrTenantRequired`, etc. being redeclared per-module is legal and, given each module owns its bounded context, arguably intended isolation. The cost surfaces at the `errors.Is` call site: nothing stops a handler from importing the wrong module's `ErrNotFound` and getting a silent false-negative (never matches, falls through to 500) instead of a compile error — the check is structurally invisible to the type system. `ErrApprovalRouteMissing` is the sharpest case: three modules (`controlleddocuments`, `documents`, `templates`) each declare their own copy of what is conceptually the same "no active route for this profile" condition, with three different message strings, meaning it cannot be handled generically across the documents/controlleddocuments/templates bounded context that ADR 0093 just ruled is one context.

**DUP-03 (tenant_data_port.go ×12).** Every module wired into `platform/tenantdata`'s GDPR export/erasure fan-out hand-writes the same ~20-line skeleton — constructor, `var _ tenantdata.Port` assertion, `Module()`, a `Tables()` slice, an `ExportTenantData` that loops `Tables()` through the shared `tenantdata.ExportTable` helper. The only per-module content is the table list and the erase-order comment. This is the platform/tenantdata coupling already flagged in the shared brief (12 of 15 modules) manifesting as literal duplicated boilerplate, not just an import-graph inversion — confirms the "hand-maintained agreement" pattern this repo is already mid-campaign against extends here too.

**DUP-08 (mechanical clone pass).** jscpd's exact-clone detector puts hand-written duplication at 53 clone pairs ≥15 lines once generated `api.gen.go` router-wiring boilerplate (expected — contract-first codegen, not hand-maintained) and test files are excluded. The concentration in `approval/infrastructure/postgres_approval_repository.go` (largest single file, 4 internal clone pairs) and `iam/infrastructure/postgres/user_area_repository.go` (2 internal clone pairs) suggests these two files in particular have grown multiple near-identical query/scan paths for closely related reads rather than a shared scan helper.

## What is actually fine

- **`api.gen.go` clones across all 15 modules' `api/` packages** (largest jscpd hits, 90-131 lines each): this is oapi-codegen output from the contract-first pipeline (ADR 0090/0091). Identical per-module router-registration shape is the *correct* outcome of generation from a shared template — it is not hand-maintained and carries no drift risk. Do not treat jscpd's raw clone count (379) as the duplication number; the hand-written subset (53) is the real signal.
- **`documents/approval` DB-level vs domain-level `ErrActorAlreadySigned` (DUP-09)** matches the stated architecture principle verbatim — "DB enforces invariants (triggers/constraints); app checks are the friendly first line." Two independent enforcement paths for one rule is the intended defense-in-depth shape here, not accidental duplication, though the identical Go identifier name across two different types is worth a naming pass separately (already surfaced as a finding for visibility, not as something to collapse).
- **`templates`' deliberate pagination deviation (50/200 vs platform 20/100)** is the one instance in DUP-05 with a written rationale in-code (`x-pagination-exempt: true`, contract-bound). This is documented divergence, not silent drift — leave it as the reference example of how a deviation *should* be recorded, and hold the other three (approval, iam, and the two identical distribution/notifications copies) to the same bar.
- **`auth`'s in-memory repository (`internal/modules/auth/infrastructure/memory/repository.go`, 30 methods) mirroring the postgres implementation (31 methods)** is kept honest by the shared `domain.Repository` Go interface (`internal/modules/auth/domain/port.go:42`) — if the two drift on method signature, the package fails to compile. It is used only from `_test.go` files (verified: `grep -rln "infrastructure/memory\""` returns zero non-test hits across `internal/`/`apps/`), so it is test-fixture duplication with a compiler-enforced parity guard, not a live-drift risk the way an untyped mirror would be.

## Unverified / needs judgment

- Whether the 20 Tx/non-Tx pairs beyond the 3 confirmed in `documents` and `templates` (DUP-04) all hand-copy rather than delegate — I spot-checked `documents` and `templates`; `taxonomy`, `controlleddocuments`, `tokens` pairs were only counted by name-match, not read line-by-line.
- Whether any of the 15 collided sentinel-error names (DUP-02) have ever actually been mis-matched at an `errors.Is` call site (i.e., already drifted into a live bug) — I found the declarations and their `errors.Is` consumers separately but did not cross-check every consumer against every declaration's import to rule out a wrong-module import.
- Whether `jscpd`'s 289 excluded generated-vs-generated clone pairs contain any hand-written outliers inside otherwise-generated files (e.g., a hand-added helper next to codegen) — filtering was by filename (`api.gen.go`, `.gen.go`) only.
