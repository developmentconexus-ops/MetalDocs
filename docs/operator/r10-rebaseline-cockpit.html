T1
Semantic State & Invariants
Who owns meaning; what the business objects are.
Closed
Core: Document ≠ Revision ≠ WorkingContent ≠ Submission. REV000 = initial issuance · REV001 = first revision · ordinals never reuseWorkingContent is the only mutable DRAFT authority; Submission is immutable exact governed attempt; title belongs to Revision; Template is an ordinary governed Document role; Release owns effectivity; at most one EFFECTIVE Revision; standalone Artifact semantic owner is removed.
T2
Governance, Effectivity & Transactions
How accepted facts change safely under concurrency.
Closed
One native business transition = one local ACID product-state transaction.Document is lifecycle serialization root; DRAFT uses generation/CAS; READ COMMITTED + narrow serialization; SUBMIT freezes exact attempt/config; one sequential Step active at a time; selectors are NAMED_USER or GROUP; Group is ANY-one; submitter/initiator cannot satisfy own human step; Release is system-owned; replacement Release atomically supersedes predecessor.
T3
Authorization & Audit
Live access truth, role bundles, domain predicates and same-commit evidence.
Closed
Authorization equation: enabled User + live direct/group RoleAssignments + static Role→Permission + scope + domain predicate = allow; otherwise deny. Launch roles: governance_admin, area_manager, author, approver, viewer, governance_viewer. Governance admin is config-only, not content/governance/audit superuser. Offboarding disables User, revokes sessions and removes memberships/direct grants while preserving historical identity. Critical governed/security changes require same-local-commit Audit.
T4
Exact Content, Storage Integrity & Restore
Prove exact governed bytes while keeping storage replaceable.
Closed
ExactContentDescriptor = SHA-256 + exact size + closed ContentFormat.Provider identity is not content identity. Managed-content handle is mechanism only. Upload goes OPEN→READY with server-derived descriptor; untrusted bytes must be malware-clean before immutable governance; create-once/no-overwrite; backup includes DB + all required exact bytes; restore is fail-closed on missing/corrupt required content, invalidates restored sessions and reconciles post-snapshot privacy/security teardown before serving.
T5
Durable Async, Search & External Effects
Small durable effects layer; no generic event platform.
Closed
PostgreSQL/River is the selected durable-job mechanism. PDF can be viewed directly; SourceOnly DOCX gets a read-only adapter; required PDF rendition is produced asynchronously and admitted against the exact Submission before Release. Renderer selection stays replaceable and must pass fidelity corpus. Search remains canonical Postgres query/view; materialized/external search is off until evidence demands it. Jobs are at-least-once and revalidate eligibility; late renderer results become no-op/reclaimable rather than semantic truth.
T6
Canonical API & Frontend Journeys
Semantic HTTP/wire laws and user-facing lenses.
Closed
API: pre-launch `/api/v1` rebuilt in place; OpenAPI 3.0.3; generated Go/TS; UUID + RFC3339 UTC; RFC9457 errors; cursor pagination; Idempotency-Key on named POSTs; ETag/If-Match for DRAFT OCC. Auth: Keycloak Authorization Code + PKCE → ApplicationSession, secure host cookie + CSRF; no local passwords/JIT. Frontend lenses: Library, My Work, Document Official/Work/History, Governance Case, Audit, Admin. Search favors current EFFECTIVE truth.

Revalidation law

Não reabrir por preferência

Protect coherence

Do not resurrect

  • standalone Artifact semantic owner
  • parallel Template lifecycle/version platform
  • generic BPM/workflow engine
  • ALL / N-of-M quorum engine without consumer
  • fresh-auth/eSignature/reassign/SLA machinery without requirement
  • generic event/notification platform baseline
  • dormant generic ETL/import framework
  • DEV/test historical compatibility
  • Distribution or Periodic Review back into Launch Core
  • legacy package/table survival by existence

Reopen only when material

  • concrete reachable failure mode
  • named customer/operator consumer
  • regulatory or contractual requirement
  • current authority contradiction
  • source/runtime evidence disproves an invariant
  • implementation evidence proves accepted mechanism cannot sustain property

Revalidation does not mean reinvention. Reopen only the composite decision whose justification changed.
